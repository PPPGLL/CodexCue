# 发布标准与验收场景

[返回首页](../README.md) · [发布流程](RELEASING.md)

当前发布级别为 **Windows x64 Beta**。每个候选版本单独验收；以实际发布的 EXE、源码提交及资源校验和为准。公开发布、合并主分支和仓库可见性是独立决定。

## 发布门槛

| 门槛 | 通过标准 | 证据 |
| --- | --- | --- |
| 关键模块 | 下方核心场景全部通过，无占位实现或已知 P0/P1 缺陷 | 源码审查、回归结果、桌面验收 |
| 干净环境 | 锁定依赖可安装，Windows CI 构建与维护检查成功 | 对应提交的 CI 运行记录 |
| 自动化覆盖 | 单元测试零失败，桌面与启动测试各连续三轮通过 | `verify.ps1` 汇总与各轮 receipt |
| 模型效果 | 短句和具体要求均能自然续写；模糊输入、干扰历史及分析限制通过；人工或代理审阅实际输出 | `--live-model` 的合成样例与质量结果 |
| 稳定性 | 旧请求不会污染新草稿；取消不中断 UI；模型保持常驻并支持手动释放；重启后设置和建议可见 | 取消、超时、释放与启动场景 |
| 包与维护 | 安装、升级、失败回退、卸载通过；配置与模型保留 | `test_install.ps1 -Bundle` |
| 完整性 | 包内文件清单、源码、许可证、Qt/PySide 对应源码和哈希一致 | `check_release.py` PASS |
| 变更记录 | Changelog、版本、功能说明和维护步骤一致；所有发布输入已提交 | 版本清单与 PR |
| 隐私 | 发布文件与测试不含真实对话、用户路径、配置或凭据 | 打包清单、公开验收摘要与内容审查 |

P0 包括数据丢失、隐私泄露或未授权发送；P1 包括核心补全、Tab、任务切换、设置或安装维护不可用。任一门槛失败都应修复并重验相关层，不能用其他通过项抵消。更换 EXE 后必须重新验收并生成匹配哈希的报告。

## 核心场景

| 用户场景 | 预期行为 | 自动验证层 |
| --- | --- | --- |
| 只写“我觉得”“你好”等开头 | 仍然尝试短句猜测，保持用户语气 | 模型回归、真实模型 |
| 布局、流程、产出等粗略意见 | 一次请求自然补充相关具体要求；通常约 80–160 字，不因字数或分类强制改写 | 单次请求单测、真实模型、桌面显示 |
| “只分析，先不修改” | 补充观察与证据要求，保持原约束 | 提示词用例、真实模型 |
| 历史里出现生成规则、旧请求 | 当前草稿决定意图；复制内容尝试修复 | 上下文过滤、真实模型干扰样例 |
| 旧版设置升级后保存并重开 | 自动续写；保留服务、模型、凭据和启用状态；无模式选项或弹窗标签 | 配置迁移、设置保存、弹窗单测 |
| 空草稿、完整问句、中文组词 | 空草稿不触发；问句不续成回答；组词期间 Tab 留给输入法 | 状态机与输入适配单测 |
| 开始打字、切换任务、发送消息 | 原建议失效，过期文本不显示 | 工作线程、状态机、桌面验收 |
| 新任务、短标题、重名任务 | 唯一匹配才使用历史；自动策略在无匹配时仅用草稿 | 任务索引、合成 UIA |
| 建议显示后按 Tab | 完整文字插入当前草稿，消息保持未发送 | 原生剪贴板粘贴回读 |
| 本地服务停顿或切换草稿 | 取消正在等待的连接；新请求继续；总时间受限 | 取消与超时单测 |
| 模型空闲、暂停、手动释放、退出 | 空闲和暂停保持模型常驻；托盘手动释放；下次输入重新加载；退出时释放 | 状态与真实 Ollama 常驻查询 |
| 隐藏脚本启动、重复启动、重开设置 | 设置、下拉框和弹窗保持 Windows 原生可见 | 三轮独立进程验收 |
| 配置损坏或保存失败 | 保留原配置备份，进入恢复状态；保存失败不修改运行配置 | 配置与设置故障注入 |
| 下载中断、包损坏、升级失败 | 可重试、拒绝损坏包、回退安装，保留用户数据 | 离线下载与维护故障注入 |

覆盖以行为场景为标准。测试数量用于追踪回归规模，不能代替语义质量、宿主兼容性或端到端证据。

## 证据的适用范围

`verify.ps1` 的桌面窗口使用合成输入，但实际执行 UI Automation、工作线程、HTTP、弹窗布局、Tab 判定和原生粘贴。真实模型阶段使用已安装的 Ollama 模型，保存样例和耗时。启动测试检查 Windows `IsWindowVisible`，而非仅检查 Qt 内部状态。

这些测试不代替具体 Codex 版本的可访问性结构、物理键盘和真实输入法检查。支持声明应附上实际验证过的 Windows、Codex 和模型版本；VS Code 目前作为实验支持发布。模型输出仍需用户决定是否采用，实际速度随模型、冷启动和硬件变化。

## Beta 边界与发布记录

- Windows 二进制暂未签名。通过同一发布页的 SHA256 校验完整性，签名属于后续发行条件。
- 更新采用下载版本包、校验、运行安装器的明确流程；回退使用上一个已验证包。
- 对未验证的宿主、输入法和硬件，不标注兼容或延迟保证。

每次发布记录：版本、提交、EXE 哈希、CI 链接、各层验收结果、已审阅的模型样例和已知边界。公开附件 `desktop-verification.json` 只含汇总数字和哈希；详细本机报告保存在 `.local/`。若仍有未解决的发布阻断项，保持草稿状态并明确列出，不使用“无风险”替代证据。
